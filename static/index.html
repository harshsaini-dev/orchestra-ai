Setup and honest limitations

Run start_rag.bat to install ChromaDB and PDF support. Copy .env.example to .env, add GEMINI_API_KEY locally, and restart the server. Then build the index. A configured key still needs model access, quota and internet.

No local embedding model is downloaded. The default offline workflow remains rule-based. RAG is enabled explicitly and fails visibly if a model call fails. Citation checks validate IDs and exact quotes, not every claim's meaning.

Uploaded documents support Q&A. Live business agents use only the governing policy collection for RAG explanations; uploaded instructions cannot grant cancellation or refund permissions.

YOUR PRACTICAL, EXPLAINED

Follow the request.
Understand the system.

OrchestraAI routes an order request through five specialised software agents. Each has a separate responsibility. The graph shows persisted request/reply messages, explicit agent states, and actual backend events.

What to show in your practical

Choose Cancellation → Start workflow. Watch Planner, Data, Policy and Decision run. The Action Agent waits for your approval. Enter your name and approve. Compare the stored order snapshot with the current record, then download the audit.

What is implemented?

Python / FastAPI backend, SQLite records, deterministic business rules, policy retrieval, document RAG with ChromaDB and Gemini citations, live server-sent events, a bounded worker queue, persisted traces, historical replay, and transactional approvals.

The default mode uses rules and works without an API key. Gemini assistance is optional and never authorises a refund. All money movements in this academic prototype are simulated.
